<Update label="v0.4.0" description="2026-11-13">

A new look (forui "Amber Brand" design system on desktop and mobile), a `yourssh` command-line client with `yourssh://` links, and a round of fixes found by driving the finished app end to end.

### Added
- **`yourssh` command-line client (phase 1, macOS, Linux and Windows, run from source)** — `yourssh connect <host>`, `ls [--json] [--tag T] [--filter Q]`, `version`, `open <url>` and `help` talk to the running app (NDJSON protocol v1) and start the app if it is not running. Hosts resolve by id, label or `user@host[:port]`; ad-hoc `user@host[:port]` works from the CLI only and signs in with the SSH agent's keys (a password-only server needs a saved host). `yourssh version` never starts the app. A debug build of the app uses its own endpoint (`YourSSH-dev`, `\\.\pipe\yourssh-cli-dev-<SID>`); the CLI reaches it with `YOURSSH_DEV=1`. macOS/Linux: a per-user Unix socket, 0600 in a 0700 run dir, that checks the peer uid. Windows: the named pipe `\\.\pipe\yourssh-cli-<SID>` with a current-user-only DACL and remote clients rejected; the app drops clients running as another user, and the CLI checks the pipe's server the same way before sending anything (a pipe owned by another user exits 4). Every request carries a token rotated at every launch, and the app is single-instance on all three (a second launch, including a clicked link, is handed to the running app before it starts anything else). Exit codes: 0 ok, 1 error, 2 usage, 3 app unreachable, 4 denied. Not yet: packaging the CLI binary in releases (today `yourssh` in a release is the GUI app) and an install button, `sftp`/`tunnel`/`import`/`export`, MCP.
- **`yourssh://connect/<host-id-or-label>` links** — open a saved host from a browser or script; saved hosts only, repeats of the same link within 2 s are ignored, and a refused link (unknown host, unsupported form) is listed in the notification bell. The scheme is registered by the macOS app, the Windows installer (current user) and the Linux .deb; the portable zip and tarball do not register it.
- **Audit source for CLI and URL connects** — SSH connect rows carry `meta.source` = `cli` / `url`; RDP and VNC rows keep `source: rdp|vnc` and carry `via` = `cli` / `url`.

### Fixed
- A new SSH session shows a single prompt; the prompt printed before the invisible shell-integration setup no longer stays behind as an empty line.
- **Snippets no longer disappear after allowing the bundled "Snippets" plugin.** Earlier builds shipped a half-migrated script copy of Snippets that moved your snippets out of the built-in plugin's storage on first load and then failed, so the next launch showed only the defaults. The script copy is no longer installed, a leftover copy in `~/.yourssh/plugins/snippets` is ignored (script plugins can't reuse a built-in plugin's id), and the moved snippets are restored once at startup (merged, no duplicates).
- Bulk "Run command" no longer reports `exit -1` for fast commands: the SSH layer kept an exit status that arrived before the session was ready. The footer counts non-zero exits separately (`N ok · M non-zero exit · K failed`) and an unknown exit status is shown as such.
- A host whose name doesn't resolve no longer sits on "Connecting…" forever: the TCP dial times out after 15 s and the connecting screen shows the last error with the retry attempt.
- Entering RDP/VNC fullscreen no longer raises a framework error; the first RDP connect shows a neutral "verifying certificate" state behind the trust dialog instead of an error with Retry; Retry buttons have a normal width.
- Shell-integration gutter markers follow their prompt line and disappear on `clear` instead of floating on empty rows.
- Field errors in the host editor and port-forward editor clear as soon as the value is fixed, and the port error fits on one line.
- The hosts toolbar fits the 900×600 minimum window (lower-priority controls collapse into a menu); the Mail Catcher and AI chat titles no longer truncate with room to spare; multi-line Web Tools editors start at the top; the mobile Generate/Import key sheets have an opaque surface; Esc closes the LAN-sync QR dialog.
- SFTP shows readable errors (e.g. '"releases" already exists') instead of raw `SftpStatusError` codes when creating or renaming.
- An empty split pane explains how to fill it; remaining all-caps buttons and titles (Keychain, Port forwarding, Audit log, bulk dialogs) use sentence case.
- **The host editor no longer leaks one host's form into another.** Opening "Edit" on a second host (or "New host" / "Duplicate") while the editor was open kept the first host's fields, and Save wrote them (including the password) into the second host.
- The terminal header and status bar follow edits to the host (label, user, tags, jump chain) instead of showing the values from when the tab was opened.
- Mail catcher: messages whose log starts with ESMTP options (`mail options: ['BODY=8BITMIME']`) are no longer dropped; the body is parsed separately from the headers, *Clear all* persists, and the log is written unbuffered in append mode.
- Port validation ("Invalid (1–65535)") in both host editors (SSH/RDP/VNC port and proxy port), port forwarding and the Cloudflare tunnel panel; an empty port keeps its default.
- Deleting a host also removes its stored proxy password.
- The mobile sync code and anonymous key are hidden behind a reveal toggle.
- The status bar also shows in RDP and VNC sessions.
- Terminal search and input bars keep or return focus correctly (Esc, Enter, clicking away).
- The read-only "Watching" banner has its own informational colour again.
- Session and DevOps result tabs can be selected and closed from the keyboard (Tab to a tab, Enter/Space to select, Tab again to its close button).
- List items in bottom sheets on mobile are at least 44 px tall.
- The Cloudflare tunnel panel shows "Required" / "Invalid (1–65535)" for a missing label or a bad port instead of silently adding nothing or falling back to 3000 (an empty port still means 3000).

### Changed
- **New confirmations:** clearing captured mail in the Mail Catcher, deleting a host from the dashboard card menu, removing a Known Hosts entry (its pinned key), Sync *Disconnect*, Docker Compose *Down* and opening an executable file externally now ask first; the safe choice has default focus.
- **SFTP click model:** on both panels a single click selects, and double-click or Enter opens.
- **Host editor:** a *Delete* button was added to the footer and the *CONNECT* button was removed.
- **AI chat:** Enter sends, Shift+Enter inserts a new line.
- **New look:** the app moves to the Amber Brand palette (warm dark surfaces, amber accent), the Inter font and a forui-based UI foundation on desktop and mobile.
- **New "YourSSH Amber" terminal theme**, the default for new installs. Existing installs keep their current terminal theme.
- Built with Flutter 3.50.
- **New sidebar** with grouped sections and an amber selected item.
- **New tab bar** for sessions, with the active tab marked in amber.
- **New toasts** for notifications, shown bottom-right on desktop.
- **UI clean-up:** a lint gate (`tool/check_ui_lint.sh`, run in PR CI) keeps Material `IconButton`/`AlertDialog`/`SnackBar`/`Icons`/`ScaffoldMessenger` out of the app and the plugin packages, remaining colour literals moved to tokens, the discovery and server-monitor sheets and the inline tab rename / fallback code editor fields moved to forui, the gate also rejecting `showDialog(`, `showModalBottomSheet` and `TextField(`, and `AppColors`/`MobileColors` are now `@Deprecated` aliases of the new tokens (kept rather than deleted, to avoid churn across ~460 call sites).
- **New dialogs** across the app; security prompts (host key, RDP certificate) now focus the safe choice by default.

<Update label="v0.3.0" description="2026-11-12">

### Performance
- **Terminal output is ~10× faster and never freezes the UI** — measured with vtebench-style corpora in a local shell (121×40, macOS): 40 MB of plain log output now takes 0.35 s (was ≈3.7 s with the window frozen), 20 MB of colored output 0.26 s, 8 MB of Unicode 0.13 s and 15 MB of full-screen TUI redraws 0.15 s — on par with Ghostty and 5–9× faster than Termius. During a flood the terminal keeps repainting at ~55 fps with no frame over 16.7 ms, and Ctrl+C stops the output in ~25 ms instead of letting a queued backlog print for seconds.
  - Parser rewrite in the xterm fork (≈10× faster: bulk text runs, no per-chunk allocation, memoized accent composition, scrollback line reuse) with a byte entry point, so output goes from the PTY/SSH channel to the parser without string round-trips.
  - Output is parsed in short time slices with repaints throttled to the display, with credit-based flow control on local PTYs (2 MiB window) and SSH (channel pause/resume) so the app never builds an unbounded backlog.
  - New glyph-atlas renderer: each glyph is rasterized once and drawn from a GPU texture, cutting a full-screen frame from ~10 ms to ~2 ms; complex cells (emoji, underline, combining marks) keep the previous path. Pixel output matches the old renderer.
  - DEC mode 2026 (synchronized output) for flicker-free full-screen redraws.

### Security
- **SSH agent forwarding:** forwarded agent channels are accepted only after the server accepted this client's forwarding request; the Keychain fallback serves only the host's own key; only identity-list and sign requests are relayed.
- **SSH transport hardening:** bounded agent frames, channel window enforcement, malformed packets fail the connection instead of hanging it, and Diffie-Hellman group-exchange parameters are validated.
- **Remote-controlled resource limits:** terminal window-resize requests are ignored, repeat counts and escape-sequence lengths are capped, RDP/VNC desktop sizes are capped at 8192 px per edge, and server clipboard text is capped at 1 MiB with a new per-host *Accept remote clipboard* switch (on by default).
- **Files:** Windows *Open with* no longer goes through the command shell; *Open externally* refuses executable file types downloaded from a server; temporary copies live in private, random folders that are removed afterwards; generated keys are private before any key material is written and never overwrite an existing key; the sudo SFTP helper path must be a known `sftp-server`.
- **Remote helpers:** kubectl arguments are shell-quoted and port-forwards bind to localhost on the remote host; MCP gateway / Cloudflare tunnel / mail catcher are stopped by PID with private temp files; HTTP/SOCKS proxy handshakes are size-limited; LAN (P2P) sync binds only the chosen interface and caps the transfer.
- **JS plugins:** per-call time limits plus memory and stack caps, misbehaving plugins are unloaded, consent is tied to the plugin's file contents, `terminal.read` can no longer rewrite output, and plugin paths can't escape the plugin folder.
- **Storage:** AI and S3 keys use the same macOS Keychain mode as host passwords, the Gemini key is sent in a header instead of the URL, recordings and the audit database are readable only by the user, and Android app backups are disabled.

### Fixed
- Terminal: no more exceptions from truncated color sequences or `ESC[1K`/`ESC[1J` at column 0; scrolling inside a scroll region and resizing after the scrollback filled up no longer corrupt the buffer (covered by a 50,000-case fuzz test).
- `.bin` files can be opened externally on Linux again.
- Code editor saves on Android no longer wrap the file in quotes.
- Local shell: a failed `execvp` no longer leaves a duplicate process; Windows command lines are quoted correctly and support non-ASCII paths.
- Mail catcher works on Python 3.12+ (falls back to `aiosmtpd`).

</Update>

<Update label="v0.2.1" description="2026-11-12">

### Security
- **Cloud sync no longer exposes the sync code** — the Supabase row id was the sync code itself, which is also the only key-derivation input, so anyone holding the project's anon key could list `sync_data` and decrypt every row, saved host passwords included. Rows are now keyed by a one-way SHA-256 of the code (the code never reaches the server); existing rows are read once from the legacy id and moved on the next push. Pull also requires the payload's authenticated inner timestamp to be newer than the last push/apply, so a replayed old ciphertext can no longer roll the host list back. Devices still on an older version keep using the legacy row until they update.
- **Terminal sharing is end-to-end encrypted and only the controlling guest can type** — the host applied every `input` event it received, and the channel was a public, plaintext broadcast keyed by a guessable 6-character code. Share codes are now `XXXXXX-XXXXXXXXXXXXXXXX` (80-bit secret), the channel name is a hash of the code, every message is an AES-256-GCM envelope, and input is applied only from the guest currently granted control. Old and new versions cannot share with each other.
- **SSH host-key pinning can no longer be bypassed by switching key type** — a server presenting a new host-key algorithm for a host already pinned under another type was trusted silently; it now raises the host-key dialog ("Host key type changed"). **Test connection** also verifies the target and every jump host instead of accepting any key, and fails closed when no verifier is available.
- **SFTP downloads cannot write outside the chosen folder** — server-supplied names such as `../x`, absolute paths or `a/..` are rejected (skipped in folder downloads, refused for single files, the external editor and the code editor); folder downloads stop at 64 levels so symlink loops can't recurse forever.
- **RDP asks before sending credentials to an unpinned server** — the first connect to a host without a pinned certificate sent the password (TLS mode) or an NTLM response (NLA) before the trust dialog appeared. The connection now stops before authentication, shows the certificate, and reconnects with the pin once you trust it.
- **JS plugin panels respect permissions** — panel messages handled natively (`ssh-exec`, `ssh-sessions`, `sftp-list`, `sftp-read`) skipped the permission check, so a plugin granted only `ui.panel` could run commands on every session.
- **macOS updates are signature-checked** — the downloaded installer must carry the YourSSH Developer ID signature (team `84T567KMYD`) before it is opened; the old quarantine-stripping step is gone. Release builds are now signed with that Developer ID and notarized by Apple.
- **Release pipeline hardening** — every GitHub Action is pinned to a commit SHA and the workflow token is read-only except for the final publish step.
- **Rust dependencies** — `rustls` 0.23.46, `rustls-webpki` 0.103.16, `h2` 0.4.20, `tokio` 1.54.1 and others bumped past published advisories.

### Added
- **"YourSSH Dark" terminal theme** (catalog 44 → 45) — the app's own color scheme, first in the visual picker and the fallback an unknown theme name resolves to: a neutral charcoal base with a deliberately desaturated ANSI set so long log output stays flat and readable, and azure/teal accents on the cursor, selection, and current search hit. The stored default for existing and new installs is unchanged (Dracula).

### Fixed
- **VNC did not work in release builds** — the release pipeline never built or bundled the VNC native library; it now ships on macOS, Windows and Linux.
- **SFTP mode "Sudo" was ignored, so browsing failed with `Permission denied (code 3)`** (#109) — every SFTP entry point is handed a `Host` snapshot captured when its panel/slot was created, and `openSftp` read the SFTP mode from that snapshot. Switching a host to Sudo/Custom afterwards therefore changed nothing: listings kept running through the plain `sftp` subsystem as the login user, with no sudo prompt and no `root` badge in the panel header (the dual-panel source picker also short-circuits when the same host is re-picked, so the snapshot never refreshed). `openSftp` now resolves the host by id at call time (`resolveSftpHost` + the `defaultHostLookup` wiring), which covers the panels, transfers, file operations, the editor, path autocomplete and mobile in one place, and the header badge reads the live host too
- **Local terminal tabs ignored the color theme** — `LocalTerminalPane` built xterm's `TerminalView` without a `theme:` argument, so every local shell rendered in xterm's built-in default palette and the Settings → Terminal color theme silently applied to SSH tabs only. The pane now resolves the global theme (local sessions have no host, so no per-host override applies).
- **Screenshot harness wrote two shots to stale paths** — the recording-library and audit-log captures went to `screenshots/09-recording/` and a flat `screenshots/audit-log.png`, neither of which the README reads, so those two images silently went stale while every run left untracked files behind. Both now write into `screenshots/10-audit-recording/` under the filenames the README references. The output root is also derived from the repo (walked up from the CWD) instead of one developer's absolute home path, and the run now fails if the README references a screenshot that is not on disk.

</Update>

<Update label="v0.2.0" description="2026-08-23">

### Added
- **Android app (development preview)** — YourSSH now targets Android as a focused mobile SSH client, sharing the platform-agnostic core with desktop. `main()` branches on `isMobilePlatform` and mounts a separate mobile UI, so no desktop code path changes. Hosts list with search / folder chips / tag grouping and live reachability probes; a `TerminalView` with an **accessory key bar** (sticky Ctrl/Alt, ^C/^D, arrows, special characters), pinch-to-zoom and long-press cursor drag; single-panel **SFTP** (browse / download / upload); **snippets** quick-run; **key** generation and import; **port forwarding** rules; host import from desktop over cloud Supabase pull or a **P2P QR camera scan**; biometric **app-lock** and the TOFU host-key dialog. The release ships an APK signed with the **debug key** — it installs and runs, but a real release keystore has to land before it can go to Play or be upgraded in place. RDP/VNC, plugins, recording and the audit log stay desktop-only.

### Changed
- **New app icon** — the launcher artwork is redrawn from a vector master instead of hand-exported bitmaps: an amber squircle (superellipse corners) with a chunky `>_` prompt glyph that stays legible down to 16 px. `tool/gen_app_icons.py` regenerates every platform target from `assets/branding/*.svg` — macOS iconset (inset to Apple's 824/1024 grid), a 16–256 px Windows `.ico`, the Android adaptive layers (gradient background drawable, foreground inside the 66dp safe circle, plus an Android 13+ themed/monochrome layer), and the in-app / README logos. Measured: the glyph holds 6.4–12:1 contrast against the amber plate and the icon reads at 6.3–7.3:1 against every dark app surface.

</Update>
